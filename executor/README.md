# Packaged UI Test Runtime

This project is shipped inside `linear-browser-qa`. Run commands from this directory after `pnpm install --frozen-lockfile`. The skill owns task interpretation and verdicts; Computer Use handles new UI paths one action at a time; Playwright handles stable actions and repeated cases.

Source changes belong in the skill source repository. Keep reusable locators and a single user intent with its observed facts together in `src/actions/`; compose actions, test data, and business expectations in `tests/release/cases/`. Before each run, inspect both existing cases and actions: reuse an applicable case after checking current expectations, deployment SHA, data/roles, and side effects; otherwise compose available actions into a new case. Explore with Computer Use only for missing actions or unknown paths. Verify new actions in a real case and with focused unit tests, typecheck, and test discovery before publishing a new skill version. Changes to an installed copy are temporary and must not be treated as the source of truth.

Runtime layout: `src/actions/` contains reusable browser intents and observed facts; `src/tools/` contains reusable test execution and CLI support (polling, evidence, stage tracking, Computer Use/exploration contracts, environment and release checks); `src/clients/` contains product API adapters; `src/session/` and `src/cleanup/` own test lifecycle; `src/report/` owns report data. The `src/` root is for runtime config and Playwright fixture/bootstrap entrypoints. `tests/release/cases/` composes Actions into business cases and owns expectations; `tests/unit/` verifies reusable components.

Before testing, create `../qa-env/.env.local` from `../qa-env/.env.example` and run `pnpm qa-env:check`. It reports the missing file or required variable names without printing values. Add `--playwright` for host-side Playwright or `--admin` when validating Admin credentials on the host. The host loads E2B credentials from this local file without overriding already injected environment variables; browser credentials inside E2B still come from its separate testenv. Never publish `.env.local` or copy it into E2B. Set `E2E_REPORT_OUTPUT_DIR`, `E2E_TEST_OUTPUT_DIR`, and `MIDSCENE_RUN_DIR` to paths under this run's `QA_ROOT/<feature>/` before executing cases. Pass an absolute `--case-dir` under its `evidence/` directory to `pnpm computer-use`.

Use `pnpm typecheck`, `pnpm test:unit`, and `pnpm test:list` to validate the packaged runtime without starting a product run. Agent QA publishes reports to artifact.cafe; `apps/report/` remains available for existing project compatibility and is not the Agent QA publishing path.

For Agent QA Playwright cases, set `E2E_AGENT_QA=true` and `E2E_TEST_OUTPUT_DIR` to this run's evidence directory. This keeps per-case videos but disables traces and the native HTML reporter. Build the published report with `pnpm report:bundle:qa --markdown <report.md> --manifest <run-state/video-manifest.json> --evidence-dir <evidence/> --output-dir <new-empty-directory>`. The manifest maps every `### Case N` heading to its video or marks it unexecuted. The output contains only the report HTML, Markdown source, and case videos; CI/CD report scripts remain separate.
