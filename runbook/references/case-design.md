# Case 设计：七个生成器

Case 不由模型自由挑选，而是按固定的七个生成器逐个推导。每个生成器有明确的输入（大多来自命中的 QA module）和产出规则；Agent 负责把规则套到本次改动上、判断适用性，并为每条机制记录是哪个生成器产出的。这样同一张单的设计可以复现，漏项可以归因到具体的生成器，再去修素材或规则。

本文件定义「怎么推」。任务模型格式见 `QA-models/_schema/ticket-task-model.md`；范围预算与去重见 [Case 覆盖与执行准确率](coverage-and-accuracy.md)；冻结与漏项记账见 [Case 漏测 Hook](omission-hook.md)。

## 输入

先完成 [取单与环境解析](intake-routing.md) 和 `QA-models/_workflow/linear-ticket-intake.md` 的前五步，得到：

- **Change Model**：本次碰了哪个 surface、entity、状态迁移、副作用；
- **Requirement Atoms**：ticket 或用户明确陈述的验收原子，各带出处；
- **命中模块**：primary 与 adjacent，以及 `model_gap`。

PR-only 时 Change Model 来自 [PR 驱动入口](pr-driven-intake.md) 的 changed-file → changeId 映射；Goal 模式来自用户目的和 [Goal Test Model](goal-driven-intake.md)。

## 七个生成器

| ID | 输入 | 产出 | 主类型 |
|---|---|---|---|
| `G1-acceptance` | Requirement Atoms | 每个原子一个机制；原子含「应被拒绝/不应发生」的再拆一个 negative | happy / negative |
| `G2-assertions` | 命中模块断言目录中 `Applies when` 与 Change Model 匹配的断言 | 回归检查；优先并入已有路径的断言，不单独开 Case | 随断言 Type |
| `G3-transitions` | 命中模块「状态模型」里被碰到的迁移 | ① 合法迁移到业务终点；② 从其他状态发起同一操作应被拒绝（非法迁移）；③ 相邻状态不应受影响 | happy / negative |
| `G4-execution-modes` | Change Model 碰到、且 Business Actions 中 `Side effect` 不是只读的动作 | 并发、重试、响应丢失、中断/刷新恢复；只在钱、权限、异步、外部交接等高代价动作上展开，按 [时序风险](temporal-risk-cases.md) 推演 | edge |
| `G5-state-pairs` | primary 模块被碰状态 × 每个 adjacent 模块的状态 | 两两组合后按下方三条剪枝规则保留的组合 | edge |
| `G6-cross-cutting` | 本文件下方固定清单 × 每个被碰到的资源/接口 | 权限、组织隔离、输入契约、刷新与重复提交 | negative / edge |
| `G7-history` | 命中模块的「待补测」「历史风险与回归探针」，以及 product-memory 中与 Change Model 触发条件相符的 Bug 模式 | 待补测中状态为 `未测` 且前置适用的条目必须纳入；历史风险按触发条件选 | 随来源 |

### G5 的三条剪枝规则

1. **剪掉不可达**：按状态模型的合法入口排除真实不可能同时出现的组合（例如草稿不会遇到广告账户被封）。不确定的标「未知」，不选有利于通过的假设。
2. **只展开高风险**：只保留涉及钱、权限、异步、幂等、外部交接的组合；普通表单、布局类直接跳过。
3. **只做两两组合**：三个以上对象的组合不全展开。

### G6 横切契约清单

对 Change Model 中每个被碰到的资源或接口，逐项判断是否适用：

| 契约 | 典型机制 |
|---|---|
| 权限 | 无权限角色看不到入口，**且**直接调接口被拒 |
| 组织隔离 | 切组织后不读写另一组织的数据；旧响应不覆盖新组织上下文 |
| 输入契约 | 边界值、超长、空值、非法格式被拒绝且不产生副作用 |
| 刷新与重复提交 | 刷新、返回、双击、多标签后状态一致，不重复产生副作用 |
| 投放树遍历 | Change Model 碰到 Agent、输入框/目标 chip、投放入口或投放流程时：命中模块「投放树」里每个可投放叶子至少起草出一份有效草稿（不 launch、不花钱）；状态为 `none` / 无入口的行核对入口不存在。叶子共用同一路径可合并成一条 Case 并写明理由 |

## 从候选到计划

1. **逐个跑生成器**：每个生成器都要有结论——产出了哪些机制，或「不适用」及一句理由。不能整组跳过不写。
2. **只收有出处的**：每个机制必须有权威 Expected（ticket / user / active 模块断言 / pr_spec）。没有出处的进候选池，并在 QA 工作台登记 C 类问题，不进计划。代码只说明实现，不能当出处。
3. **按失效机制去重**：不同生成器推出同一机制时合并，`generator` 记最先、最直接的那个。同一路径能顺带验证的断言并入一条 Case，不拆数量。
4. **排序与预算**：G1 全部纳入；G7 中待补测全部纳入（不占 smoke 预算）；其余按「失败代价 × 发生可能」排序，普通 ticket 默认在验收之外再加两条，高风险改动说明理由后扩展。预算外的写明排除原因。
5. **可测性预判（规划时就做，不要等执行时才发现）**：先读命中模块的「不可测与不设计」一节，命中的条目直接按其「处理」栏记状态；其余入选 Case 再判断本环境和本轮能不能到达它的业务终点。已知到不了的**不排执行、不尝试**，直接在计划里标 `Blocked` 并写**具体恢复条件**；仍计入分母，不因此从覆盖率剔除。典型情形：
   - 需要完整的真实生命周期才能观察：广告投出后要等 admin 审核、跑数天才有上报数据（实时看不到的 Overview 更新、首个有数据日、与平台数据对账）；
   - 需要我们没有的环境操作：重启 API、重新部署环境、改基础设施配置，或需要第三方真实故障；
   - 需要真实花钱且结果要过很久才可见的动作（钱包扣费本身已预先授权，但不等于能观察到后续结果）。
   前置在本环境根本不存在的状态（例如所有新用户都走 onboarding，不可能出现“没填网站”）标 `NotApplicable` 并写依据，剔除分母单列；用户明确决定不测的标 `SkippedByConstraint` 并写出处。拿不准是否可达时，先用一次只读核对（不超过几分钟）确认，再决定；确认不了就标 `Blocked`，不要为此搭环境。
   这样既不浪费执行时间，也不会因“没跑”而让报告看起来比实际更全。

6. **冻结**：把机制与 Case 写进 `omission-plan-input.json`，每个机制带 `generator`，按漏测 Hook 冻结后再执行。

任务模型的 `tasks[].kind` 沿用原五类（acceptance / module_invariant / adjacent_contract / historical_risk / recovery），同时为每条任务填写 `generator`。对应关系通常是：G1 → acceptance，G2/G3 → module_invariant，G5/G6 → adjacent_contract，G7 → historical_risk，G4 → recovery。

## 漏项归因：让生成器变强

人工或复核指出漏项（工作台 D1）时，除了按工作台规则补测，还要归因，并写进漏测账本的 finding：

- `generator`：本该由哪个生成器产出；没有任何生成器能覆盖时填 `none`。
- `generatorGap`：
  - `material`——生成器存在，但模块缺素材（例如状态模型少一个状态、Business Action 没标副作用、断言缺 `Applies when`）。修法：补模块（走工作台 C 类审核）。
  - `rule`——没有生成器规则能推出它。修法：给对应生成器加一条规则（改本文件，例如 G6 清单加一项），或在确实是新类别时提出新增生成器。

`omission:hook summary` 按生成器汇总：计划了多少机制、确认漏了多少、漏在素材还是规则。长期看哪个生成器漏得多、哪个产出的 Bug 多，决定先补哪里。没有生成器标注的旧计划计入「未归因」，不能回填。

## 模块需要提供的素材

生成器质量取决于模块素材。审阅或补充模块时检查：

- 状态模型列出合法入口、终态，以及**非法迁移**（哪些状态下哪些操作应被拒绝）——G3 的输入；
- Business Actions 的 `Side effect` 填写准确——G4 的输入；
- 断言目录每条都有 `Applies when`——G2 的输入；
- 「待补测」与「历史风险」有触发条件——G7 的输入。
- 「不可测与不设计」列出已知到不了或已裁定不测的检查，含处理方式和恢复条件——规划时第 5 步的输入；人在复测或评审中得出新的裁定，经 QA 工作台映射写入这一节。

缺这些时，相应生成器只能产出候选或记 `model_gap`，并在归因时记为 `material`。
