# 执行前发现时序风险 Case

这是 TLA+ 案例启发的轻量推演方法，不运行 TLA+/Lean，也不声称穷举或形式化证明。用于补充原 checklist/Goal cases，不改写其中的 Expected，不成为 E2B 执行的前置依赖。

## 何时使用

在权威 Expected、适用条件和命中模块明确后，执行准备前做一次快速筛选。只有当前目标同时涉及异步状态、并发、重试、缓存、取消或外部回调，以及较高的失败代价（钱、权限、任务丢失、重复提交、错误投放）时，才继续推演。普通表单、CRUD、布局和低影响单步操作跳过，不为凑数新增 Case。

## 如何推演

1. 写出当前业务对象的初始状态、终点和权威不变量。Expected 来自 ticket、用户明确要求或适用的已审核 QA-model；产品源码只用于理解事件语义，不能定义正确结果。
2. 只列与风险有关的少量事件：请求发出/结果到达、提交/回执、重试/原请求完成、取消/异步回调、缓存读取/刷新、worker 重启/回收。**发出和到达分开**，检查其间能否插入其他事件；不要把真实异步链压成一步。
3. 手工比较几种现实可能的次序，重点问：旧响应能否覆盖新状态？重试会否造成重复副作用？取消后迟到的回调会否改变终态？已付费/已提交对象会否永远 pending？把“不可能发生”的次序以源码或规则说明排除；不确定的库/第三方语义标为未知，不能选有利于通过的假设。
4. 对每个有价值的次序，形成候选 Case：前置与角色、关键事件顺序、权威 Expected、可采集的 UI/只读业务事实、副作用及安全重试边界、与现有 checklist 的关系。没有可判定 Expected 或可行观察面的，只记开放风险，不冒充可执行 Case。

## 纳入与执行

- 原 checklist 保持独立；新增项标记 `risk-derived` 并注明依据和覆盖的业务目标。优先合入已有路径的断言；确需独立路径时，普通 ticket 默认最多选两条相关风险 smoke，额外独立高代价风险须说明理由。Goal/repeat 按用户范围选择，避免无关全量回归。
- 推演只是提出候选，不是发现产品 Bug，也不是证明未列出的次序安全。候选仍需通过 [Browser 执行与恢复](execution.md) 的数据/副作用门槛，在 E2B 中由 Computer Use 或 Playwright 真实执行，采集每 Case 视频和确定性事实。
- 失败按 [判定与复现](verdicts.md) 排除规则、环境、数据和自动化问题；未能复现的时序只能记未验证风险或 Inconclusive。不得用模型信心、纸面交错或代码推测给 Pass/Product bug。
- 在本轮任务模型的风险部分记录筛选结果（启用/跳过及原因）、已选 Case 的时序和假设、未选候选的原因。分析应短于实际测试；遇到状态空间过大、事实不足或需要 TLA+/Lean 才能判断时停止推演，照原计划执行，不安装工具或阻塞 Case。
